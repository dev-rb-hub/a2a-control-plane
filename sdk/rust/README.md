# a2a-control-plane Rust SDK

The second implementation of the [a2a-control-plane](../../README.md) specification, after the Python reference SDK. It is not yet published to crates.io (`publish = false`).

## Status

| Layer | Modules | Status |
|-------|---------|--------|
| Wire types | `proto`, generated by `prost` from `schemas/v1` with a vendored `protoc` | implemented |
| Core (pure logic, no I/O) | `tokens`, `identity`, `subjects` (grammar, wildcards, ACLs), `state`, `heartbeat`, `capabilities`, `payloads` (framing, task digest, challenge payload), `voucher` (Ed25519 signature check), `backoff` | implemented, checked against `conformance/vectors` |
| Roles (Aggregator, Worker client) | | planned: [#14](https://github.com/dev-rb-hub/a2a-control-plane/issues/14) |
| gRPC transport with mTLS (`tonic`, `rustls`) and interoperability with the Python SDK | | planned: [#14](https://github.com/dev-rb-hub/a2a-control-plane/issues/14) |

Not implemented in the core: the Aggregator's voucher checks after the signature (spec 04 Section 4.4), the replay store, delta and state views, and the task ledger. They belong with the roles.

## Design

The crate follows [RFC 0005](../../rfcs/0005-async-model.md): the core is synchronous and free of I/O, and time is always an argument. Transports will sit at the edge on an async runtime.

## Commands

```
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
```

No system `protoc` is needed. The tests read the vectors from `../../conformance/vectors`, so run them from a full checkout.
